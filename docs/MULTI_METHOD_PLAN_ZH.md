# Name That LLM：多种可行方法的详细实验方案

日期：2026-10-28，Asia/Shanghai。目标：提高正式比赛成绩。独立新方法、复现公开方案、改进已有方法和融合都可采用，不要求围绕某条旧方法开展。

比赛：[Name That LLM](https://www.kaggle.com/competitions/name-that-llm)。公开研究入口：[Code](https://www.kaggle.com/competitions/name-that-llm/code)、[Discussion](https://www.kaggle.com/competitions/name-that-llm/discussion)。本交付直接保存有效提交的代码与回执，不以账号提交页面或排行榜代替实验资料。

## 2. 八条路线与建议顺序

| 路线 | 核心方法 | 优先级 | 现有材料与新增工作 |
|---|---|---|---|
| A | 跨 prompt 的监督对比学习，可选内容残差 | 高 | 独立新建模；需实现采样、损失与训练 |
| B | 多个开放语言模型的概率指纹 + 判别器 | 高 | 独立新建模；需实现流式 scoring 特征 |
| C | 头/中/尾片段 + 文本结构的多视图分类器 | 高 | 独立新建模；复用部分 CPU 风格特征 |
| D | 清洗、筛选公开生成数据，做来源匹配 | 中高 | 可独立试验，也可支持 A/C |
| E | 真实验证另一条公开大型集成 | 中 | 已有固定源码和工具，缺真实运行/评分 |
| F | 对 0.636 定向消融、替换成员和分配预算 | 中 | 可选，不是新方法的前置任务 |
| G | 不完整群组下的软去内容与分布校准 | 探索 | 依赖任一分类器，需要压力测试 |
| H | 可信 OOF 上的互补融合，可选蒸馏 | 有结果后高 | 汇总有效成员，需交叉拟合校准/融合 |

第一轮优先 A、B、C 的最小版本；有现成输入时可以同时验证 E。只有一张卡时先 C 或 A 的小编码器版本，再 B 的单 scoring 模型。复用相同对照，不重复训练相同配置，也不重复提交已确认完全相同的 0.636。

显存和耗时均需实测。规划起点：小编码器在 16–24GB 卡上做小批量试验；4B/8B 特征与 LoRA 根据精度、长度、梯度检查点、量化等规划 24–48GB 或更高资源。权重装得下不等于训练装得下。本地没有 GPU，当前先交付方案和可转移的有效材料，不假装已完成 GPU 验证。

## 3. 统一验证：让不同路线的结果可比较

### 划分与训练边界

1. 保存一份 5-fold `prompt_id` 分组划分。重复/近重复文本和外部 prompt 同源项也要归组，不能只比较整数 prompt ID。
2. 向量器、PCA、标准化、类别中心、投影、分类头和校准器只在训练侧拟合。训练可均衡采样，验证保留自然分布。
3. 基础模型未使用比赛标签微调时，可预提冻结特征。已在全量比赛标签上训练过的公开 LoRA 对验证折预测，不能叫无泄漏 OOF；只重训分类头不能修复底座泄漏。
4. 全量 final 模型用于提交；评估要使用外层训练折模型。现有 LoRA24 交付有 final 和 OOF 汇总，缺完整逐折预测，不能直接用于学习融合权重。
5. 先固定两个开发折做快速筛选，入选配置跑完五折。反复研究时保留未用于开发的 prompt 做确认，或用嵌套验证；不要把开发选择过的结果冒充完全独立检验。

### 指标和继续条件

主指标为 pooled OOF Balanced Accuracy，同时保存每类 recall、混淆矩阵、每折成绩、长度/代码比例/题材切片、预测分数和运行成本。弱类根据这次真实 OOF 确定，不照抄旧报告的名单。

比较同一批样本，按 prompt 做配对 bootstrap，观察差值区间和跨折一致性。早期可把 `+0.005 BA` 当继续投入的经验筛选线，它不是统计显著性标准或收益保证。单模型持平但错误明显互补的候选可保留用于融合。单折小涨不值得直接扩大为几十个模型搜索。

### 完整推理预算

先用真实未见验证文本 64–256 行测吞吐、不同长度的峰值，再计入加载、tokenization、全部分支和后处理。相对当前官方上限留约 20% 实测余量。没有隐藏测试规模时报告不同规模假设，不把三行预览时间当完整隐藏耗时。

## 4. 路线 A：跨 prompt 学习来源风格

### 为什么值得试

同一模型在不同题目中的表达习惯可能相对稳定；同题目、不同模型的回答又能作为强负例。直接利用这两个方向的监督，有机会减少题材捷径。这是本次面向比赛提出的实验组合，不宣称学术首创。

[Model Attribution in LLM-Generated Disinformation](https://arxiv.org/abs/2407.21264) 研究将模型归因视为域泛化并采用监督对比学习。其域和模型不同，论文成绩不能直接迁移到本比赛。

### 最小实验 A0/A1

- 用 [microsoft/deberta-v3-base](https://huggingface.co/microsoft/deberta-v3-base) 建立普通交叉熵 18 类对照 A0。
- A1 使用同样步数、折分、token 预算，增加 projection 和 normalized embedding。正例为同模型不同 prompt，重点负例为同 prompt 不同模型。
- 每个真实对比 batch 包含多个 prompt、每类多个实例。梯度累积不会自动扩大一次对比损失的负例集合，需要显式采样或正确实现队列。
- 第一轮只比较 `L=CE` 和 `L=CE+lambda*SupCon`，`lambda={0.1,0.3}`，温度先固定 `0.1`。
- 同一回答不同片段可作为额外 view，单独消融；不做任意重写或删除标点，以免破坏来源信号。
- 比较 softmax 头和训练侧最近类中心，确认收益体现在分类，而不只是 embedding 图更好看。

### 可选 A2：不依赖测试分组的内容残差

仅在 A1 有价值后尝试。在训练侧计算每个 prompt 的均衡多模型中心 `c_p`；用另一内容表征 `s(x)` 回归中心，得到 `g(s(x))`。比较 `h(x)` 与 `h(x)-alpha*g(s(x))`，`alpha={0.25,0.5}`，保留 `alpha=0` 控制。

回归器、中心和分类器只使用训练侧，训练侧再交叉拟合检查过拟合。预测只看当前文本，不需要真实测试 prompt ID 或完整 18 条组。内容减法也可能误删来源特征，无增益即删，不因为理论听起来好就保留。

### 资源与交付

先用 16–24GB 卡、长度 512、小批量；确认长文截断有损后再扩长度。随后可用 [Qwen3-4B-Base](https://huggingface.co/Qwen/Qwen3-4B-Base) 比较冻结多层特征或 LoRA，不能直接复制 LoRA24 的层号。交付采样配置、A0/A1/A2 对照、OOF、逐折权重与吞吐。A1 跨折无收益时停止扩展 A2；可靠 A0 仍可作为独立成员。

## 5. 路线 B：多语言模型概率指纹

### 核心假设

用几个开放模型读取同一文本，提取 token 选择和局部不确定性的统计，再监督识别 18 类来源。评分模型不是比赛标签的真实生成模型；Qwen 给文本较高概率不意味着它来自 Qwen，需要训练数据学习判别关系。

### 最小实验 B0/B1/B2

1. B0 从 [Qwen3-4B-Base](https://huggingface.co/Qwen/Qwen3-4B-Base) 开始，做 causal next-token scoring：正确 shift，mask padding，不生成文本，不向输入加入真实来源标签。
2. 固定原文区间，提取 NLL 均值、分位数、方差、低概率 token 比例、head/tail 差值等；有必要再加词表熵和 top-k gap。
3. logits 按 batch/chunk 流式聚合，不能保存 `样本×长度×词表` 张量。截断/滑窗边界和首 token 的处理写进配置。
4. 先标准化 + 正则 LogisticRegression，标准化及分类头均在训练折内拟合。B1 增加 CPU 风格统计，判断是否存在互补。
5. 有独立信号后，B2 增加 [HuggingFaceTB/SmolLM2-1.7B](https://huggingface.co/HuggingFaceTB/SmolLM2-1.7B)，顺序加载，避免为并行多占显存。
6. 不同 tokenizer 的 NLL/entropy 不直接相减；保留各自特征，或按原文 byte/字符数归一后单独消融。先测前 512 token，再比较 head/tail 与滑窗，检查长度是否成为唯一捷径。

第一轮有效后才考虑每类小 adapter/软提示的 source-conditioned likelihood；这与已有 ATLAS 有关联，要独立计成本，不是 B0 的前置依赖。

### 资源与取舍

单模型先用 16–24GB 或更高显存探测，统计分类器在 CPU 训练。量化与精度改变单独记录。交付评分模型 revision、tokenizer、shift/mask 自检、逐行特征、OOF 和速度。第二 scoring 模型也无独立贡献时停止加模型。二分类 AI 检测的高分不能证明这条路线能做 18 类归因；这里不继承任何其他任务成绩。

## 6. 路线 C：分段和结构风格的多视图分类器

### 核心假设

开头应答、正文组织、结尾总结可能包含不同来源信息。只截断前文会丢信号；过度清洗又会抹掉 Markdown、标点和段落习惯。

### 实验 C0–C3

- C0：单段 DeBERTa-v3-base。与 A0 相同配置时复用，不重复训练。
- C1：同一共享编码器分别读 head/middle/tail，每段先 192 token，拼接 mean/max 或轻量 attention pooling，再分类。短文本使用有效片段 mask，避免复制三段。比较总 token 预算相同的单段模型，排除只是多读文字。
- C2：增加段落、列表、标题、代码围栏、标点 bigram、功能词等结构分支；可复用 [CPU 组件](../methods/cpu/README.md)。POS 分布是可选后续依赖，先测不用 POS 的版本。
- C3：仅根据外层训练侧错误分析，针对混淆类对加正则 pairwise 头，与全局模型软融合。不按手写 provider 名单硬路由，以免第一级错误无法恢复。

### 依据与风险

[Your Large Language Models are Leaving Fingerprints](https://aclanthology.org/2025.genaidetect-1.6/) 为词汇/形态句法差异提供动机，不证明本比赛同家族细分类有效。[Through the Looking Glass](https://aclanthology.org/2021.eacl-main.155/) 是生成模型归因先例，旧数据集数字不作为这里的预期。

用长度分层、同长度比较和来源模板审计检查捷径。结构信号可以有用，但若只是外部数据模板痕迹，则不应泛化。先用 16–24GB 卡共享编码器小批量测试，交付单段/分段/结构三项 OOF、逐类变化和成本。此模型可以独立提交，不依赖原 0.636。

## 7. 路线 D：高质量外部数据与来源匹配

不默认额外数据越多越好。[原 32 项输入](../verified/score_0636/MODEL_SOURCES.md)中有文本池、权重和 Notebook 输出，先区分类型，不能把权重 Dataset 当语料。

1. D0 固定一个 A0/C0，用官方数据建立对照。
2. 为每个 pool 记录 URL、版本、真实生成模型、system/user prompt、采样参数和清洗过程；未知项标注。相近模型名不能直接映射成比赛标签。
3. 做 exact hash、近重复、prompt 语义重合及数据源模板检查。外层验证同源/近重复从全部外部训练池移除；来源标签无法确认的样本不用硬监督。
4. D1 只新增一个最可信 pool，外部 loss 权重先比较 `0.25,1.0`。D2 先外部预训练，再用官方训练折适配。
5. D3 在训练侧依据内容/长度/风格匹配筛选外部样本，阈值由内层验证选择。验证比例不人为改成训练采样比例。
6. 以官方外层 OOF 决定保留；外部自测好、官方变差就停用。每次只增加一个来源，能归因才继续扩大。

资源为 CPU 清洗和既有分类器训练。新生成数据只在渠道已经授权、规则允许时考虑，不能假设有付费 API，也不能把另一模型重写的回答冒充原模型样本。交付来源清单、排除原因、权重和 D0–D3 结果，不重复托管第三方原始语料。

## 8. 路线 E：验证另一条公开大型集成

起点为 [公开原方案](https://www.kaggle.com/code/mohammedafreedpasha/name-that-llm-solution)，已保存 V25 的实际代码、33 项输入和严格运行工具，见[固定 GitHub 版本](https://github.com/Kidding-Ma/ntl-complement-gpu-handoff/tree/debdb0781600566bd4d211ea7e2f324546124d92)。

必须先读[源码审计](../evidence/v25_source_audit.md)：文字引用 0.651，但实际代码与文字不同，Llama v5=1.5、DeBERTa=1.3、ATLAS=0.16/margin=0.38，且主动 `NTL_DROP_Q35=1`。没有该版本正式分数，不能叫已复现 0.651。

执行顺序：按 manifest 获取原资产，检查访问权限、版本和 shard；忠实运行所有成员；保留进程退出码和混合日志；检查 COMP/ATLAS 是否被捕获异常后跳过；覆盖长测试的 Sinkhorn、margin 和 ATLAS budget 分支。少于 18/50 行时代码有不同逻辑，三行不能验收全部分支。

输入齐全且完整运行成功后，才能列为待提交候选，取得它自己的真实成绩。缺权重时可以做独立命名的修改版，不能用别的 adapter 改名冒充。此路线下载和推理成本高，先核算磁盘、显存、RAM 及官方时限；有现成输入时有价值，但不阻塞 A/B/C 的独立研究。

## 9. 路线 F：现有 0.636 的定向改进（可选）

已实测结构为主分支四项、12 个 complement 成员和 ATLAS。主/complement 混合约 `0.85/0.15`，低 margin 行再加 `0.10 ATLAS`，大测试批量运行 Sinkhorn；精确行为以[已评分源码](../verified/score_0636/ntl_complement_fixed.ipynb)为准。

- F1：保存各分支未后处理概率，测边际贡献和错误重合。公开 checkpoint 若见过官方验证标签，这些只能标记为污染诊断，不能宣称泛化提升。
- F2：将[自训 LoRA24](../methods/lora24/README.md)作为新成员或替换候选，与不换做受控比较。旧权重与新训练目标/头不同，旧融合系数不能直接继承；0.4793 OOF 不能证明它会改善 0.636 LB。
- F3：固定 ATLAS 总预算，比较基于 margin、模型分歧和校准不确定性的选择。阈值来自训练侧无泄漏验证，记录更多行/少量计算与少量难行/较强计算的取舍。
- F4：删去高相关且无边际贡献的昂贵成员，把推理预算给 A/B/C 的独立模型；成员越多不一定越强。

没有干净 OOF 时冻结旧集成做真实 LB 对照，优先研究新模型，不在泄漏 CV 上盲调几十组系数。这条路线不强制执行。

## 10. 路线 G：软内容去除和弱分布校准

这是探索路线。隐藏批量未必有完整 prompt 组或均匀类别。本地历史研究出现过 assignment OOF 好看而实际迁移负面的现象，因此不默认使用强约束。

在外层验证样本上构造 pseudo-test，覆盖完整组、仅 2/4/8 条、随机缺类、同题重复来源、噪声合并、类别先验偏移和行顺序打乱。使用文本可观测信号分组，不能用验证真标签帮助恢复组。

比较独立预测、保守软中心化和弱先验校准。分组可信度用相似度/稳定性控制混合权重；不使用推理时拿不到的真实 prompt ID。Sinkhorn、Hungarian 和一类一个作为单独强假设对照，不能当默认事实。先固定 base logits，分开归因模型与后处理的贡献。

交付各场景矩阵、最差切片和独立预测回退逻辑。只在人工完整 18 条组有效、缺类即崩溃时，不列为正式默认。缓存特征后主要用 CPU；若分组器也利用比赛标签，它同样必须遵守外层边界。

## 11. 路线 H：可信 OOF 融合与可选蒸馏

输入按[结果规范](EXPERIMENT_CONTRACT.md)保存。确认每行的训练模型和外部语料没有见过对应验证标签，按 ID 对齐并核对类别顺序。只有汇总分数、没有逐行预测的成果不能训练融合。不同折分可以对齐样本，但要记录训练边界，同名 fold0 不代表同一划分。

1. H0：最佳单模型和等权平均概率作控制，计算错误交集、模型分歧和各类贡献；单模略弱但能修正别人的错，仍有价值。
2. H1：交叉拟合温度校准、少量非负且和为 1 的权重，比较概率平均和 log 概率平均。SVC margin 不当成校准概率直接相加。
3. H2：确有多折证据时才上强正则 LR stacking 或软 pairwise expert。融合器在外层评估样本之外拟合；全 OOF 调权重再报同一 OOF 会乐观，需嵌套/交叉拟合或独立保留集。

先保留 2–4 个互补成员，类级权重和门控在 2699 行上容易过拟合。组合超预算时可将训练侧教师分数蒸馏到较小模型，重新验证；蒸馏只是压缩候选，不保证提升。

正式融合须在同一次 Kaggle 隐藏重跑中动态生成各成员预测并对齐，不能融合本地三行 parquet 来冒充隐藏结果，也不能假设可以下载其他提交的逐行隐藏预测。

## 12. 第一轮有限实验清单

| 顺序 | 实验 | 主要改变 | 下一步条件 |
|---|---|---|---|
| 0 | 固定数据、折分、已评分回执和输入版本 | 无 | 建立可比较的证据，不重复相同提交 |
| 1A | A0 vs A1 | CE vs 跨 prompt 对比 | 稳定才试 A2 内容残差 |
| 1B | B0 vs B1 | 单 LM 指纹 vs 加风格 | 有信号才扩第二 scoring LM |
| 1C | C0 vs C1 | 等 token 预算单段 vs 分段 | 有收益才加 C2 结构 |
| 2D | D0 vs D1/D2 | 一个可信 pool 及训练方式 | 官方外层验证支持才保留 |
| 2E | 固定 V25 运行 | 另一公开方案 | 完整运行后取得其自己的分数 |
| 3 | 入选方案完成五折与互补分析 | 验证第一轮发现 | 少数成员进入融合 |
| 4 | H0 vs H1 | 等权 vs 校准融合 | 结果稳定且推理可行才列正式候选 |
| 5 | F/G 可选 | 旧成员、预算或软后处理 | 有余量且有明确依据才投入 |

这是最小实验集，不是所有组合一起搜。新模型明显占优时可以完全替换旧集成；公开新方案更强也可直接采用。目标是实际成绩，不是维护既有技术路线。

## 13. 交付和完成标准

每个完成实验提供代码 commit、配置、数据与模型 revision、折分、硬件、训练/推理时长、逐行 OOF、每类结果、对照、失败尝试和判断。附重跑入口、必要权重/可访问地址及校验，具体格式见[结果规范](EXPERIMENT_CONTRACT.md)。没有跑过的功能和新方法明确标记为待实现/待验证。

最终入选方案应能在当前 Kaggle 环境禁网重跑，拥有完整输入和全部成员完成证据，生成与当前官方 schema 一致的 `id,model` 文件；记录 Notebook 版本、代码和分数回执的对应。保存运行不等于已提交，最终评分提交由用户选择，避免盲搜消耗次数。

## 14. 文献和方法的适用范围

仅将与生成来源分类有关的证据映射到实验，不堆无关论文。训练数据来源归因、权重指纹、人机二分类均不直接等于本比赛的多类生成模型归因。

- [Model Attribution in LLM-Generated Disinformation](https://arxiv.org/abs/2407.21264)：A 的跨域监督对比动机，不证明本比赛效果。
- [Through the Looking Glass](https://aclanthology.org/2021.eacl-main.155/)：生成来源分类先例，旧成绩不迁移。
- [Your Large Language Models are Leaving Fingerprints](https://aclanthology.org/2025.genaidetect-1.6/)：C 的风格特征动机，同家族细分类仍需验证。
- [TRACE](https://arxiv.org/abs/2407.04981)：检查方法后其 source 主要围绕源材料/知识来源，不当作当前来源模型分类的直接复现。

基础模型入口：[Qwen3-8B-Base](https://huggingface.co/Qwen/Qwen3-8B-Base)、[Qwen3-4B-Base](https://huggingface.co/Qwen/Qwen3-4B-Base)、[SmolLM2-1.7B](https://huggingface.co/HuggingFaceTB/SmolLM2-1.7B)、[DeBERTa-v3-base](https://huggingface.co/microsoft/deberta-v3-base)。执行时固定具体 revision、tokenizer 与环境，不把不断更新的 main 当作可复现版本。
